# 开发与定制

NotaVoy 是一个完整 Obsidian 仓库模板。`99-系统` 存放模板与 Bases 定义，`.obsidian/plugins/project-tasks` 存放随附插件，`main.js` 就是可直接阅读和修改的源码，不需要打包。

## 数据约定

| 对象 | 目录 | 识别字段 | 关联方式 |
| --- | --- | --- | --- |
| 项目 | `10-项目` | `类型: 项目` | `参考知识` 链接知识笔记 |
| 任务 | `11-任务` | `类型: 任务` | `项目` 链接项目笔记 |
| 想法 | `00-收件箱/想法` | `类型: 想法` | 可选 `项目` 链接 |
| 学习 | `20-知识/学习` | `类型: 学习资料` | 可选 `项目` 链接 |
| 开源项目收藏 | `20-知识/开源项目` | `类型: 兴趣项目` | 通过来源链接原仓库 |
| 论文 | `20-知识/论文` | `类型: 论文` | `主题` 链接主题笔记 |
| 知识笔记 | `20-知识/笔记` | `类型: 笔记` | `主题` 链接主题笔记 |
| 主题 | `20-知识/主题` | `类型: 主题` | 在正文嵌入主题内容数据库 |

项目与任务插件自动处理指定目录第一层的项目、任务、想法、学习资料、论文和开源项目收藏；主题与知识笔记使用核心模板插件手动插入。文件扩展名为 `.md`。

双链写入 YAML 时使用引号，例如：

```yaml
类型: 任务
项目: "[[10-项目/你的项目名称]]"
状态: 待办
截止日期:
```

字段为空时不推断优先级、日期或分类。“进度”是手动数值，“已完成 / 已取消”作为结束状态参与筛选。

## 修改分类与界面

分类、任务状态、项目状态、优先级可以在插件设置中修改，运行配置会保存到插件的 `data.json`。这个文件默认被 Git 忽略。若修改模板的默认选项，请同步修改 `main.js` 顶部的 `DEFAULTS`；若修改优先级语义，还要同步修改标签和 `.base` 中的优先顺序公式。

首页样式位于 `.obsidian/snippets/工作台.css`，列表、表单与按钮样式位于插件的 `styles.css`。当前使用 Obsidian 自带主题变量，没有绑定主题包。

## 修改目录、属性和章节

这些名称是工作流的接口，重命名时需要同步修改：

- **目录**：`main.js` 中的 `folder`、`kindFromPath`、`captureKindFromPath`、`KnowledgePicker` 和 `template`；`.base` 的文件夹过滤；配置中的模板、日记、新笔记与附件路径；首页、模板及书签中的链接。
- **属性**：插件读写字段、`.base` 公式与过滤、模板 frontmatter，以及 `.obsidian/types.json`。
- **章节**：插件的 `CAPTURE_SECTIONS` 与模板中的“参考链接与课程”“灵感与想法”保持一致；“目标与完成标准”和“要做什么”用于写入新建表单中的描述。

项目页保留 `project-actions`、`project-capture`、`project-order` 代码块，才能显示对应操作按钮。项目任务、参考知识和主题内容数据库依赖当前页面上下文，通常应从项目或主题笔记的嵌入视图查看。

## 开发与验证

复制一份模板作为测试库。用 Obsidian 打开它，在修改源码后重载插件；不要在实际使用的知识库中开发。

本项目兼容基线为 **Obsidian 1.14.4**。插件用到 Bases 扩展 API，也沿用了针对 `metadataTypeManager` 的属性编辑行为定制；后者属于内部接口，后续 Obsidian 版本升级需要重新验证。没有对移动端、Windows 或 Linux 做兼容性承诺。

修改工作流时，至少走通受影响的操作：创建项目与任务、确认关联视图、修改属性；涉及资料、排序或删除时，再检查相应流程。JavaScript 的基础语法检查可以使用：

```sh
node --check .obsidian/plugins/project-tasks/main.js
```

## 模板公开范围

提交通用模板、数据库、样式、插件源码和虚构示例。个人笔记、附件、回收站、窗口状态和插件 `data.json` 不属于模板发布范围。

`.gitignore` 按文件名明确允许现有示例，其余数据目录内容默认忽略。添加新的公开示例时，需要同时调整忽略规则。该规则无法阻止已经跟踪的文件泄露后续写入的信息，提交前仍要检查暂存内容。

本项目不复制 Obsidian 程序，不附带第三方插件二进制、论文原文或云盘备份脚本。插件运行时由 Obsidian 提供 `require('obsidian')`。项目自身的文件按根目录 MIT 许可证发布。
